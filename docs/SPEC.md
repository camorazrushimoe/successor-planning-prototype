## Данные · пул

Единственный справочник людей — локальный файл `prototype/people.json` по [DATA_CONTRACT.md](../DATA_CONTRACT.md).

Это не мок. В демо кладётся боевая выгрузка ~200 профилей юнита. В git может лежать короткий сэмпл — его нельзя считать источником правды. Имена вроде Maria Iyer / Pavel Orlov — только fallback, если файл не прочитался.

Правило загрузки:

1. `fetch('people.json')` успешен и `people.length > 0` → **весь** пул UI = этот массив. Fallback-каст выключается.
2. «+ из пула», incumbent при создании/едите роли, селект Candidate — только `id` из этого файла.
3. Поиск в модалке пула: `name`, `title`, `id`, `level`, `track`.
4. Уже стоящие в planned / recommended / incumbent этой роли из списка добавления исключаются.
5. Если в сиде роли прототипа зашиты старые mock-id, и их нет в выгрузке — карточка роли остаётся, но слоты с неизвестным id не рисуются. Пользователь набирает людей заново из файла.

Выгрузку в git не класть.

## Комментарии к профилю

Коммент — не черновик в textarea, который пропадает. Это лента на паре **человек × роль**.

Поля записи:

| поле | смысл |
|---|---|
| `text` | текст |
| `by` | `head` \| `hr` \| `observer` |
| `at` | ISO datetime добавления |

Правила:

- Unit Head и HRBP **пишут** и видят всю ленту.
- Observer только читает.
- Candidate **не видит** комменты Head/HR и не пишет в эту ленту.
- Пустой текст не сохраняется.
- После «сохранить» поле очищается, запись появляется в списке на той же карточке (имя роли-автора + время + текст).
- Лента живёт в сессии прототипа (перезагрузка страницы сбрасывает — ок для демо). Не пишется обратно в `people.json`.
- Коммент 9-box при калибровке HR — отдельная обязательная запись того же треда (`by: hr`).

Баг текущего прото: textarea есть, сохранения и списка нет. Это нарушает 0.8.
