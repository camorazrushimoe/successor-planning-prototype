# Спецификация прототипа

## Контекст

Большая аутсорс / project-delivery компания. Юнит ~150 инженеров (в жизни до 200): delivery + практики (platform, mobile, QA, data).

Клиенты на аккаунтах. Ключевой риск — уход Delivery/Engineering Partner: клиент, маржа, бенч.

Это не «кадровый резерв на всех». Succession только на критические роли, которые создаёт Unit Head.

## Пользователи

| Роль | Что делает |
|---|---|
| Unit Head | Создаёт карточки ролей, назначает incumbent, planned/recommended successors, двигает горизонт готовности, отмечает цели |
| HRBP | Калибрует 9-box (drag + обязательный комментарий), видит все 8 ролей, флаг «нужен ассессмент» |
| Кандидат | v1 не видит чужие slates. Опционально позже — только свои цели |

## Фреймворки в продукте

1. **Critical roles, не org chart.** Роль заводит босс и называет сам («Delivery Partner — Nordics banking»), это не штатка 1:1.
2. **Slates, не один наследник.** На роль: 1–2 planned + recommended из пула. Emergency cover отдельно.
3. **Горизонты готовности:** `ready_now` / `6m` / `12m` / `18m`.
4. **9-box:** performance × potential. Звёзды и high-potential — основной вход в recommended.
5. **Leadership pipeline (Charan, упрощённо для аутсорса):** IC → stream lead → team/tech lead → account/delivery lead → partner. Готовность = набор проходов, не курс.
6. **Evidence-based readiness.** Горизонт двигается вручную после закрытых целей + комментария. Магии нет.
7. **Talent pool + поиск по 150.** Recommended считает прототип по правилам (ниже). Planned ставит босс.
8. **Каденция.** Квартальный check-in по целям, годовой talent review (калибровка 9-box).

## Флоу v1

1. Босс создаёт роль: имя (свободный текст) + зачем роль критична.
2. Указывает incumbent (поиск по JSON).
3. Опционально указывает planned successor(s).
4. Система показывает recommended (скоринг).
5. Босс/HR собирают slate, цели, emergency cover.
6. По ходу квартала отмечают цели → статус on_track / at_risk / ready.
7. Сдвиг горизонта только с причиной (лог).

## Правила recommended (прототип)

Скоринг кандидата на роль:

- не junior, не сам incumbent;
- potential medium/high;
- пересечение track / skills с success profile роли;
- performance high даёт бонус;
- сильный client feedback (score ≥ 4.3) — бонус (в аутсорсе это почти must);
- lead/architect/principal — бонус на партнёрские роли;
- уже стоит planned на другую критическую роль — штраф (не сжигать один bench на всё).

Топ-5 по скору = recommended. Босс может добавить кого угодно из 150 поиском.

## Что не в v1

Оргчарт на 150, чат, автопромоушен, полноценный competency catalog, интеграция с Workday.

## Данные, на которых должен работать UI

У человека в компании (и в seed) есть:

- тайтл, уровень, трек, локация, английский, утилизация, bench risk;
- навыки;
- клиентские проекты (клиент, домен, роль на проекте, срок, импакт);
- фидбек клиента / аккаунта;
- толки с руководителем / HRBP;
- performance, potential (вход в 9-box; HR может перекалибровать в UI).

Карточка человека в UI показывает эти блоки коротко: не «ещё один HR-профиль», а доказательства, почему человек в slate.
