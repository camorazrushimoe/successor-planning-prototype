# Интерфейсы прототипа

Три экрана + модалка создания роли. Навигация: **Pipeline | Матрица**. Карточка человека — drawer / `/people/:id`.

Визуальный тон: плотный enterprise. Мало хрома, много состояния покрытия.

---

## Как работать с экранами

|Экран|Кто основной|Зачем пришёл|
|---|---|---|
|Модалка «Новая роль»|Unit Head|Завести критическую роль, не собирать весь slate|
|Pipeline|Unit Head, частично HR / Observer|Увидеть дыры, добавить planned|
|Матрица · 9-box|HRBP + Unit Head на review|Калибровать performance × potential|
|Матрица · таймлайн|Unit Head, Observer|Понять, кто ready к какой дате|
|Карточка человека|Unit Head|Отметить цели, сдвинуть горизонт|

---

## Общие элементы

Шапка: юнит, Unit Head, HRBP, last talent review, счётчики «нет ready-now / at risk / on track».

Бейджи: `planned` · `recommended` · `emergency`.

Готовность: ready_now / 6m / 12m / 18m.

Трек плана: on_track / at_risk / stalled / ready.

Любое изменение готовности или 9-box → короткий коммент обязателен, пишется в activity log.

---

## Экран 0. Создание роли

### Как работать

1. Unit Head жмёт **Новая роль** только когда пустое место убьёт клиент / практику / P&L.
2. Имя — своим языком, не штатное: `Delivery Partner — Nordics banking`.
3. Incumbent обязателен (поиск по 150).
4. Planned — можно пусто. Сначала роль должна существовать как дыра.
5. Save → карточка на Pipeline, recommended досчитываются сами.

HR и Observer модалку не открывают.

---

## Экран 1. Pipeline

### Как работать

**Unit Head, еженедельно**

1. Смотрит счётчики в шапке. Если «нет ready-now» > 0 — открывает эти карточки.
2. На карточке: planned пустой → берёт человека из recommended или из поиска 150.
3. Ставит primary / backup, emergency cover.
4. Клик по человеку — на карточку, чтобы завести цели.

**HRBP** — фильтр «есть дыра», кнопка «запросить калибровку», если на роли висят некалиброванные звёзды.

**Observer** — только счётчики и красные баннеры, без редактирования.

Пустые planned-слоты не прятать.

## Экран 2A. 9-box — как читать и калибровать

Не оценка «хороший/плохой». Это карта, в кого вкладываться как в successor.

### Схема клеток

Оси: **performance →** (как работает сейчас), **potential ↑** (потянет ли роль выше).

```
potential ↑
high     | загадка        | алмаз          | звезда
medium   | слабый         | ядро           | сильный IC
low      | на выход       | стабильный     | эксперт
         low               medium           high   → performance
```

|Клетка|Что значит|Что делать в succession|
|---|---|---|
|Звезда|high × high|Приоритет slate, цели под следующий проход|
|Алмаз|medium × high|Развивать: stretch, не primary «на вчера»|
|Эксперт|high × low|Держать на текущей роли. Не тащить в partner «из уважения»|
|Сильный IC|high × medium|Бакап на горизонте 12м, если есть клиентский сигнал|
|Ядро|medium × medium|Не slate, если нет отдельной причины|
|Загадка|low × high|Разобрать: нетот роль или переоценка|
|Стабильный / слабый / на выход|—|Вне процесса succession|

В аутсорсе:

- performance = поставка + фидбек клиента + работа без пожара;
- potential = сигнал на следующий проход: люди, аккаунт, спор с клиентом, P&L.

JSON `performance` / `potential` — **черновик клетки**. Живая клетка — после калибровки HR.

9-box ≠ готовность. Клетка = «в кого вкладываться». Горизонт ready-now / 6m — цели на карточке человека.

### Как HR калибрует

Сессия на этом экране, раз в квартал или перед закреплением primary.

1. На сетке только slates + high-potential, не все 150 (фильтр «все» — исключение).
2. Unit Head говорит: «это звезда, ставим primary на Nordics».
3. HR открывает превью / карточку: фидбек клиента, толк, уровень.
4. Если не сходится — **перетаскивает** в другую клетку. Комментарий обязателен (почему не звезда). Это лог.
5. Одна линейка на все 8 ролей: нельзя, чтобы каждый партнёр калибровал «своих» мягче.
6. Спорная клетка на критичной роли → флаг 360 / ассессмент.
7. Один high/high не primary на трёх ролях — HR ставит предупреждение «bench горит».

После калибровки recommended пересчитываются: звезда выше, эксперт без потенциала — не в топ.

HR **не** ставит planned и **не** двигает горизонт. Только клетку и коммент.

Unit Head видит факт калибровки, Observer — read-only.

Если через квартал звезда не закрыла цели — HR имеет право сдвинуть клетку вниз на следующем review.

## Экран 2B. Таймлайн

### Как работать

Строки — роли. Колонки — now / 6m / 12m / 18+.

1. Пустая колонка now = роль не покрыта. Observer смотрит сюда первым.
2. Цвет чипа = жив ли план (не горизонт). Горизонт = колонка.
3. Unit Head таскает чип по времени только с комментарием («цели 3/5, сдвигаем 12m → 6m»).
4. Сюда не заводят роли и не пишут цели.

## Экран 3. Карточка человека

### Как работать

**Unit Head**

1. Смотрит доказательства слева: проекты, фидбек, толк.
2. Проверяет цели справа. Нет целей — заводит 3–5, привязанных к проходу (не «пройти курс»).
3. По факту: **Достиг** / **Не готов** / **Сдвинуть горизонт**. Сдвиг — с причиной.
4. Чип на таймлайне обновляется сам.

**HRBP** — блок калибровки и флаг 360. Не отмечает «достиг» за босса.

**Observer** — чтение.

---

## Состояния

- 0 ролей: CTA «Создать первую критическую роль».
- Роль без successor: красный баннер.
- Человек в двух slates: «bench горит».
- Нет прав HR: 9-box read-only.
