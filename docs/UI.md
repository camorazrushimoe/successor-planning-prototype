# Интерфейсы прототипа

Три экрана + модалка создания роли. Навигация сверху: **Pipeline | Матрица**. Карточка человека — третья страница / drawer справа.

Визуальный тон: плотный enterprise, не «HR-портал 2014». Мало хрома, много состояния покрытия.

---

## Общие элементы

Шапка:

- юнит, имя босса, HRBP;
- дата last talent review;
- счётчики: роли без ready-now / at risk / on track.

Роли в продукте помечаются бейджами:

- `planned` — босс явно выбрал;
- `recommended` — система;
- `emergency` — закроет роль завтра.

Готовность — чип цвета:

- ready_now — зелёный;
- 6m — сине-зелёный;
- 12m — жёлтый;
- 18m — серый.

Трек плана: on_track / at_risk / stalled / ready.

Любое изменение готовности или 9-box → короткий комментарий обязателен, пишется в activity log.

---

## Экран 0. Создание роли (модалка с Pipeline)

Босс нажимает **Новая роль**.

Поля:

1. Название роли — свободный текст. Плейсхолдер: `Delivery Partner — Nordics banking`.
2. Зачем критична — 1–2 предложения (клиент / практика / P&L).
3. Incumbent — поиск по людям (имя, тайтл, трек). Обязательно.
4. Planned successor — опционально, мультивыбор, 0–3 человека.
5. Success profile (короткий чеклист): must-have компетенции, 3–5 штук. Можно оставить дефолт для партнёрской роли: Client trust / Delivery ownership / People leadership.

После Save:

- роль появляется карточкой на Pipeline;
- recommended пересчитываются и показываются на карточке блоком «система предлагает»;
- если planned пустой — карточка в статусе `дыра: нет planned`.

Не заставлять заполнять slate целиком в мастере. Сначала роль существует.

## Экран 1. Pipeline — доска 8 ролей

Главный экран босса и HR.

Сверху фильтры: роль / готовность / «есть дыра» / track.

Сетка карточек ролей (2 колонки на десктопе).

Карточка роли:

```
[имя роли, редактируемое]          criticality
Incumbent: Имя · Title
Риск: нет ready-now | один successor | цели просрочены

PLANNED
  ● Имя  9-box  6m  3/5 целей  on_track   primary
  ● Имя  ...

RECOMMENDED
  ○ Имя  score  why (одна строка)
  [Добавить в planned]

Emergency cover: Имя
[Добавить из пула 150]
```

Действия:

- drag planned между горизонтами (6m → ready_now) + коммент;
- primary / backup;
- открыть человека;
- скрыть recommended, если уже в planned;
- HR: «запросить калибровку».

Пустые слоты не прятать — пустой planned должен кричать.

Value: 20 секунд на вопрос «где дыра в юните».

## Экран 2. Матрица

Переключатель: **9-box | Таймлайн**.

### 2A. 9-box

Оси: Performance → , Potential ↑.

На клетках аватарки:

- по умолчанию только люди из slates + high potential не-junior;
- фильтр «все 150».

Клик — превью: на какую роль ведут, горизонт, главный гэп.

HR может перетащить между клетками. Комментарий обязателен. Босс видит факт калибровки.

Звезда (high/high) подсвечивается как приоритет в recommended.

### 2B. Таймлайн готовности

Строки — 8 ролей. Колонки — now / 6m / 12m / 18+.

В ячейках чипы людей (planned жирные, recommended тонкие).

Цвет чипа = track_status, не горизонт (горизонт = колонка).

На чипе мини-прогресс целей `3/5`.

Пустая колонка now у роли = красный gutter «не покрыто».

Drag чипа по оси времени = смена прогноза.

## Экран 3. Карточка человека

Drawer или отдельный роут `/people/:id`. Операционная, не LinkedIn.

Шапка: имя, title, level, target-роль, горизонт, 9-box, track_status, owner развития (босс / HR).

Колонка доказательств (из JSON):

- навыки;
- 2–3 проекта: клиент, роль, импакт;
- последний client feedback (score + цитата);
- последний talk с руководителем.

Колонка плана:

- критерии роли: есть / частично / нет;
- цели: статус, дедлайн, evidence, кто отметил;
- кнопки босса: Достиг / Не готов / Сдвинуть горизонт;
- лог.

HR-блок: комментарий калибровки, флаг 360 / внешнего ассессмента.

Value: через полгода видно, план живой. Чип на таймлайне желтеет, если цели не закрываются, а дата ушла.

---

## Состояния и пустые экраны

- 0 ролей: Pipeline с одним CTA «Создать первую критическую роль».
- Роль без successor: красный баннер на карточке.
- Человек в двух slates: предупреждение «bench горит на двух ролях».
- Нет прав HR: 9-box read-only.

## Прототип на JSON

UI читает `data/unit.json`.

Запись в прототипе: изменения ролей/целей/9-box живут в памяти + `localStorage`, исходный файл не обязателен к записи. Позже — отдельный `state.json`.

Поиск людей — клиентский фильтр по name, title, track, skills.
